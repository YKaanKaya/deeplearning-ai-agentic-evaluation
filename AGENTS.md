# Project capture instructions

## Goal

Help Kaan learn Evaluating and Improving Agentic Applications and preserve genuine work in this project. The intended local root is C:\Users\kaank\Evaluating and Improving Agentic Applications. Future GitHub and portfolio work should be grounded in these artifacts.

## Workflow

- Read this file, README.md, COURSE_PROGRESS.csv, and the current lesson/lab notes before continuing. Inspect existing files before editing.
- Work at the learner's pace. A request to capture course work is not permission to claim that unseen lessons were reviewed or unrun notebooks succeeded.
- For each lesson, read the available lesson material fully, record a useful original summary, explain its methods, and link the relevant source. Distinguish course statements, personal observations and proposed extensions.
- For each lab, inspect the actual notebook and supporting tree. Preserve the course's notebook cell order, filenames, helper modules, data layout, and relative imports. Put additional experiments and commentary outside the original notebook structure unless the learner asks for an edit.
- Before execution, save a baseline when possible. Never reset a workspace to obtain a baseline if that would discard learner work.
- Execute in the approved lab environment or an accessible local project. Preserve failed attempts and fixes. Verify completion from outputs and error state; execution counts alone do not prove a clean run.
- After execution, save/checkpoint, download the executed notebook and available supporting files, and confirm the downloaded artifacts. Record the actual destination. A click on Download is not proof that the requested Windows folder was updated.
- Capture dependency versions, model/configuration settings, data versions, evaluator rules, results, errors, and interpretations. Never record credential values.
- Update the current CAPTURE.md, lesson notes, method index, progress tracker, and portfolio evidence as appropriate. Only record measured results with source artifacts and run identifiers.
- Do not fabricate transcript content, results, notebook files, certificate completion, personal reflections, or tested installation commands. Mark gaps explicitly.
- Use original summaries rather than copying entire lecture transcripts. Preserve source attribution.
- Raw course downloads and run outputs are excluded from Git by default. Prepare reviewed publication copies only after checking applicable redistribution terms and removing credentials/private data. Do not apply a blanket license to third-party materials.
- User will launch GitHub and portfolio work later. Do not create/publish a new repository or modify the portfolio merely to capture a lesson.

## Access honesty

The initial capture was built in a separate workspace and delivered as a ZIP. It did not inspect or write the Windows folder. A future agent must confirm its actual local access before claiming to update that path. Browser access alone does not imply local filesystem access. If direct access is absent, provide a clearly named update package and identify what the learner needs to place in the local folder.
